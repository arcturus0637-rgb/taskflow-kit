# 검증한 것과 남은 확인

최근 검증일: 2026-11-10. 실제 실행 환경은 Windows, Python 3.14.3이다. 아래 결과는 이 로컬 배포물의 동작에 대한 확인이며 대회 점수나 임의 과제의 정답 보장이 아니다.

## v1.2 모델 설계·개선과 의사결정

전체 자동 검사 **59개가 통과**했고 건너뛴 항목은 없다. [실행 로그](test-results-v1.2.txt)를 포함한다. 기존 46개에 새 모델/개선 스킬·참고 파일 설치 관련 검사 3개와 모델 배정 검사 10개를 추가했다. 새 파일의 양쪽 설치, 불완전한 스킬팩과 필수 정책이 없는 소스의 설치 전 거절을 확인했고, 설치 자체가 사용자 승인이나 채택 기록을 만들지 않는 것도 확인했다.

총 8개 스킬의 frontmatter와 UI 메타데이터를 확인했다. 새 절차는 스킬 지침과 일반 로컬 기록이며, 승인 강제 엔진·모델 실행기·상시 개선 서비스를 구현한 것은 아니다. 기존 작업판 명령과 검증 상태를 사용자 채택 승인으로 해석하지 않도록 연결했다.

모델 배정 검사에서는 basic Luna 6/low, standard Sol 6.1/medium, critical Sol 6.1/high를 확인했다. 미지원 모델에서 자동 대체하지 않고, Astra·허용하지 않은 라벨·기본값 별칭·자동 업데이트 활성 정책을 거절했다. Terra 5.6은 ID 미확인 상태를 유지하며 Terra 6.1·Sol 5.6으로 대체하지 않고, Sol 6.0은 명시적 대안 요청에만 선택했다. `agent-plan`의 출력은 에이전트 실행·업데이트·승인 수행이 없음을 구분한다. 현재 지원 목록은 호출자 관찰값이며 이 도구가 계정 권한이나 호스트를 독립 검증하는 것은 아니다.

별도의 읽기 전용 검토자는 실제 배정 함수를 실행해 같은 경계를 확인했고 중요한 추가 결함을 보고하지 않았다. 문서 정리에는 gpt-6-luna/low, 이 검토에는 gpt-6.1-sol/high를 native 도구에 명시적으로 요청했다. 반환 정보에는 실제 적용 모델의 별도 확인값이 없었으므로 요청 모델을 실제 적용 모델로 단정하지 않는다. 비용·속도·품질 우열을 측정한 실험은 아니다.

별도 소비 에이전트가 구현 코드를 수정하지 않고 새 스킬을 사용해 네 개의 가상 요청을 수행했다. 실제 응답과 계획·판단·검증 기록을 분리된 평가 폴더에 작성했고, 원본 CSV·현재 채택 포인터의 SHA-256은 전후 동일했다.

별도의 읽기 전용 검토에서 단일-root 작업판과 후보별 작업 사본 경로의 혼동을 찾았다. 같은 공통 root 아래 실제 후보 접두사 경로를 예약하고 실제 cwd를 별도로 전달하도록 보완했다. 공통 root를 쓸 수 없으면 조율 기록/순차 모드를 사용하며, 여러 독립 작업판이 전역 충돌을 막는다고 주장하지 않는다.

새 배포물을 압축한 뒤 다른 폴더에 풀어 매니페스트 검사, dry-run, 총 8개 스킬의 새 프로젝트 설치, 같은 바이트 재설치를 실행했다. 기존 지침·CSV 입력을 보존하고 실제로 다른 접두사 경로의 두 후보 작업을 동시에 예약한 뒤 두 Python 후보를 실행했다. 기본 구현은 바뀌지 않았고 설치된 `check` 명령도 실제 후보 소스에서 실행했다. 이 로컬 실행은 native 에이전트 메시지를 보낸 시험과 구분한다. 문서·스킬의 로컬 링크도 검사했다.

이전 upstream 고정 소스와 라이선스는 수정하지 않았다. Understand Anything 그래프 실행·새 의존성 설치·실제 대회 적용·숨겨진 평가 접근은 이번 변경의 검증 범위가 아니다. 기존 설치의 다른 바이트를 자동 덮어쓰거나 전역 설정을 변경하지 않는다.

## 이전 v1.0·v1.1 자동 실행 검사

v1.0의 전체 표준 라이브러리 unittest 검사 43개가 통과했다. v1.1에서는 Understand Anything 통합 검사 3개를 추가해 **46개 모두 통과**했다. 건너뛴 항목은 없다. [v1.1 실행 로그](test-results-v1.1.txt)와 [기존 상세 로그](test-results.txt)를 함께 둔다.

확인한 주요 동작:
- 네 개의 실제 Python 프로세스가 같은 수정 범위를 동시에 예약할 때 단 한 작업만 시작한다.
- 독립 경로의 동시 작업은 허용하고 상하위 디렉터리·같은 파일·공통 자원의 읽기/쓰기 충돌은 차단한다.
- 기존 담당자가 바쁜 상태에서 다음 요청이 등록되며, 선행 작업이 단순 완료된 상태에서는 시작할 수 없고 실제 통합 기록 뒤에 준비된다.
- 요청 재시도로 작업이 중복 생성되지 않고, 변경된 같은 키의 payload는 거절한다. 담당자가 없던 요청을 나중에 명시적으로 배정할 수 있다.
- 전송 여부 불명·실패 상태를 보존하며 이를 착수나 완료로 오인하지 않는다. 성공 native receipt가 없는 delivered 기록은 거절한다.
- 차단된 우선 작업 때문에 무관한 준비 작업이 사라지지 않는다. 순차 모드는 실제 실행 예약 한도가 1이다.
- 잘못된 상태 전이·다른 담당자의 완료 처리·중단 확인 없는 예약 해제를 거절한다.
- Windows 점/공백 경로 별칭과 NTFS junction을 통한 수정 범위 우회를 차단한다.
- 실패·시간 초과·검사 중 변경·검사 후 변경·다른 작업/프로젝트의 실행 증거를 성공 검증으로 사용하지 못한다.
- 기존 AGENTS.md와 과제 파일의 바이트를 보존하고, 설치 사전 확인과 같은 바이트 재설치가 동작한다. 충돌 시 기존 파일을 덮어쓰지 않는다.

Python 3.10 문법 호환성을 검사했다. 3.10/3.11에 없는 Path.is_junction API를 제거한 조건에서도 실제 NTFS junction을 거절하는 회귀 검사를 실행했다. **Python 3.10 인터프리터 자체와 Linux에서는 실행하지 않았다.**

## 소비 에이전트의 실제 사용 평가

구현과 테스트 코드를 읽지 않은 별도 소비 에이전트가 다섯 스킬·운영 안내·CLI 도움말을 읽고 서로 다른 두 상황을 수행했다. 실제 작업판 명령 30개와 관찰 확인 14개를 실행했다.

- CLI 과제: 원본 ID 보존·입력 불변·빈 입력을 요구사항으로 유지했다. 웹 대시보드는 선택 사항으로 남겼고 예시 임계값을 필수 정답으로 고정하지 않았다. native 병렬 기능이 없는 조건에서 순차 모드를 사용했다.
- 앱 변경 요청: 계산·입출력·화면 작업이 진행 중인 상태에서 CSV를 입출력 담당, 다운로드 UI를 화면 담당에게 연결했다. 공통 응답 계약을 읽는 세 작업이 유지되는 동안 계약 변경의 쓰기 예약은 차단됐다. 시간 초과 메시지는 unknown으로 보존했고 동일 요청 재시도로 작업이 추가되지 않았다.

이 평가는 실제 작업판·예약·대기열을 실행했으며 가상의 target에 native 메시지를 보냈다고 주장하지 않았다. assignment 자체의 CLI 구현이나 실제 UI·CSV 기능 완성은 평가 범위가 아니었다.

## 깨끗한 프로젝트 설치와 연결 실행

빈 과제 폴더에 지침·CSV 입력과 두 독립 소스를 준비해 dry-run과 설치를 실행했다. 두 독립 작업의 동시 예약, 바쁜 담당자의 후속 요청, 통합 전 후속 작업 거절, 통합 후 시작, 실제 CSV 출력 실행·ID 대조·증거 검증까지 연결했다. 입력 CSV와 기존 지침의 SHA-256은 전후 동일했다. 전달 상태는 unknown으로 남겨 실제 메시지 전송과 구분했다.

별도 검토자가 찾아낸 미배정 요청의 후속 배정 누락, Windows 파일 별칭 우회, 오래된 pathlib API의 junction 우회는 실패 재현 후 수정했다. 검토자의 집중 재검사에서 세 문제 모두 해결됨을 확인했다.

## 공개 원본과 배포 무결성

기본 세 공개 저장소의 26개 선택 파일과 v1.1에 추가한 Understand Anything 원본 385개에 대해 고정 커밋 Git blob SHA-1·크기와 로컬 SHA-256을 확인하고 원본 라이선스를 보존했다. 라이브러리·참고 스크립트의 존재를 실제 실행 성공으로 표시하지 않았다.

ZIP에는 스킬·표준 라이브러리 도구·공개 참고 원문·라이선스·검사를 포함한다. 임시 작업판 DB, 평가용 실제 출력, 개인 설정, 키, 대회 비공개 자료는 포함하지 않는다. 배포 시 전체 파일 매니페스트를 만들고 ZIP을 새 폴더에 풀어 매니페스트 및 프로젝트 설치를 다시 확인한다.

## 실제 본선에서 확인할 항목

- 제공 Codex의 native 하위 에이전트 도구·실제 동시 실행 한도·스킬 발견 방법.
- 개인 스킬/공개 저장소/설치/외부 도구에 관한 **본선** 규칙.
- 실제 과제의 실행 환경·출력 형식·평가 기준·최종 제출 동작.

수정 예약은 협력 규칙이고 OS 차원의 쓰기 차단이 아니다. 원격 전송의 정확히 한 번 처리, 자동 모델 실행, 상시 요청 감시, 임의 자식 프로세스 트리의 완전 종료, 실제 대회 환경의 전체 동작은 이 팩의 검증 결과로 주장하지 않는다.

## v1.1 Understand Anything 추가 확인

원본의 스킬 9개·패키지 6개와 필요한 에이전트·스크립트를 포함했다. 새 프로젝트 설치 후 `$understand` 연결 스킬과 원본 `build-fingerprints.mjs`·project-scanner의 존재, 설치된 원본 경로, 기존 legacy 데이터 폴더 보존, 잘못된 프로젝트 거절을 실제 명령으로 확인했다.

별도 소비 에이전트가 설치와 `understand-status`를 실행해 실제 설치 경로·플러그인 경로·원본 skill 경로를 확인했다. Node 24와 pnpm 11은 관찰됐지만 원본 코어는 빌드하지 않아 `core_built=false`, `ready=false`, `performed_analysis=false`였다. 패키지 설치·원본 전체 그래프 생성·대시보드 실행은 수행하지 않았다. [이 팩의 소스 기반 설명](UNDERSTAND.ko.md)은 해당 파이프라인 실행 결과와 구분한다.

사용자의 마지막 지시에 따라 Understand Anything은 **최종 구현·통합·검증 다음**에 적용하도록 연결했다. 설치가 금지된 환경에서는 그 제한을 밝히고 소스에 근거한 한국어 설명을 제공하며, 실행하지 않은 그래프를 완성했다고 표시하지 않는다. 그래프 이후 구현이 바뀌면 기존 그래프와 관련 검증을 오래된 결과로 보고 갱신한다.
