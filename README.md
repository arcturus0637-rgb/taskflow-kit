# TaskFlow Kit 1.3.0

처음 보는 과제를 이해하고, 작동하는 모델을 만든 뒤, 사용자와 합의한 범위에서 개선안을 비교하는 범용 스킬팩입니다. 여기서 모델은 AI 모델만이 아니라 **입력부터 출력까지 목적을 수행하는 전체 방식**을 뜻합니다.

- **과제와 모델 정의:** 원문 근거, 입력·출력의 의미, 목표·제약·평가 기준을 정리합니다.
- **최소 완성 흐름:** 실제 입력부터 결과까지 연결하고, 모듈별 방법은 과제 목적에 맞춰 선택합니다.
- **병렬 작업:** 프론트엔드·백엔드의 독립 모듈이나 서로 다른 후보를 실제 에이전트 도구로 나누어 진행합니다.
- **승인된 개선:** 실행 배치를 먼저 보고·논의하고 승인받습니다. 현재 채택 모델을 보존한 채 제한된 실험과 독립 비평을 수행하며, 개선 후보 채택에는 매번 별도 승인이 필요합니다.
- **최종 결과물 이해:** 구현·통합·검증 뒤 Understand Anything을 적용해 구조·동작·선택 이유와 한계를 한국어로 설명합니다.

TaskFlow 조율 도구는 Python 3.10+ 표준 라이브러리를 사용합니다. Understand Anything 그래프 실행에는 별도로 Node.js ≥22, pnpm ≥10과 원본 코어 빌드가 필요합니다. 실제 모델 실행·에이전트 실행·메시지 전달은 제공 AI 환경의 native 도구가 담당하며, 병렬 도구가 없으면 순차 모드로 사용할 수 있습니다.

## 가져오기와 등록

```sh
git clone https://github.com/arcturus0637-rgb/taskflow-kit.git
python taskflow-kit/kit.py verify-bundle
python taskflow-kit/kit.py install --project /path/to/actual-project --dry-run
python taskflow-kit/kit.py install --project /path/to/actual-project
```

`/path/to/actual-project`를 실제 과제 폴더로 바꾸세요. Python 실행 이름이 `python3`이면 명령도 바꾸세요. 새 프로젝트에 TaskFlow 스킬 7개와 `$understand` 연결 스킬 1개, 총 8개를 설치합니다. 기존 과제 파일과 `AGENTS.md`는 보존하며, 내용이 다른 기존 설치가 있으면 중단합니다. 조용히 업그레이드하거나 기존 설치를 삭제하지 않습니다.

## 에이전트별 모델 배정

기본 작업은 Luna 6·낮은 추론, 일반 구현은 Sol 6.1·보통 추론, 핵심 설계와 중요한 검토는 Sol 6.1·높은 추론을 기본으로 합니다. 허용 목록은 Sol 6.1·Terra 5.6·Luna 6·Sol 6.0이며 **Astra는 금지**합니다. Terra 5.6은 현재 도구에서 정확한 모델 ID가 확인되지 않아 미확인 상태로 보존하고, Terra 6.1이나 Sol 5.6으로 바꾸지 않습니다. Sol 6.0은 승인 범위에서 명시적으로 선택할 수 있는 대안입니다.

오프라인 `agent-plan`은 관찰한 지원 모델 목록과 배정안을 대조하며, 에이전트 실행·사용자 승인·부모 모델 변경은 하지 않습니다. 실제 호출에는 도구가 지원하는 정확한 모델과 추론 수준을 명시합니다. **키트·모델·스킬·의존성·설정은 자동 업데이트하지 않습니다.** [배정 규칙과 한계](skills/taskflow-parallel/references/model-routing.md)를 따릅니다.

## 시작 요청

실제 과제 세션에서 다음과 같이 요청하세요.

```text
$taskflow-workflow을 사용해 이 과제를 진행해줘.
COFA 환경이라면 읽기 전용 시작 점검부터 하고, 실제 지원·문서 기재·미확인을 구분해 운영 모드를 제안해줘.
원문 근거로 입력·출력의 의미, 목표·제약·평가 기준을 정리하고 실제 입력부터 출력까지 연결되는 최소 모델을 제안해줘.
사실, 내 선호, 검증 전 가설을 구분하고, 우선순위가 충돌하면 임의 가중치를 정하지 말고 나와 논의해줘.
먼저 작업 범위·완료 기준·실험 한도·복구 방법을 실행 배치로 보고하고 내 명시적 승인을 받아줘. 승인된 범위의 구현과 검사는 이어서 진행해줘.
실제 도구가 있으면 독립 모듈이나 경쟁 후보를 병렬로 맡기고, 독립 비평자에게 원문 요구와 실제 결과를 함께 검토하게 해줘.
현재 채택 모델을 보존하고 개선 후보를 공정하게 비교해줘. 범위 변경과 각 개선 후보 채택은 다시 논의하고 내 승인을 받아줘.
채택 후에는 실제 통합 결과를 검사하고, 승인 범위에서 새 모델의 실패·병목·약점을 진단해 다음 실험을 제안해줘. 승인받지 않은 다음 배치는 시작하지 마.
최종 구현·통합·검증 뒤 $understand로 구조·데이터 흐름·선택 이유·검증과 한계를 한국어로 설명해줘.
```
