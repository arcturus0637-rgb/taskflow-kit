# TaskFlow Kit 1.0

처음 보는 과제를 빠르게 이해하고, 독립 작업을 여러 에이전트에 나누며, 진행 중 들어온 요청을 담당자의 다음 작업으로 이어주는 범용 스킬팩이다. 특정 반도체 문제나 프레임워크에 맞춘 정답·완성 앱을 포함하지 않는다.

## 구성

| 스킬 | 역할 |
|---|---|
| taskflow-workflow | 과제 확인 → 최소 결과 → 병렬 작업 → 검증 → 제출 준비 |
| taskflow-brief | 원문 근거가 있는 요약과 필수/선택/예시/가정 구분 |
| taskflow-parallel | 백엔드 내부를 포함한 작업 분할·담당 범위·공통 자원 조율 |
| taskflow-inbox | 사용자 개선 요청 보존·다음 작업 등록·실제 메시지 전달 상태 구분 |
| taskflow-verify | 통합·실행·검증·제출 상태 구분과 오래된 검사 결과 거절 |

공개 오픈소스의 디버깅·검증·리뷰·문제 분해·단순화 문서를 고정 커밋 원문과 라이선스 그대로 보관하고 필요한 단계에서만 참고한다. [정확한 출처](docs/SOURCES.ko.md), [운영 예시](docs/OPERATIONS.ko.md), [검증 범위](docs/VALIDATION.ko.md)를 확인하면 된다.

## 요구 환경

Python 3.10 이상과 표준 라이브러리 SQLite를 사용한다. 계정·API 키·MCP·패키지 설치는 필요하지 않다. 병렬 실행에는 **제공된 AI 환경 자체의 하위 에이전트 기능**이 필요하다. 이 팩은 모델 실행기나 백그라운드 감시 서비스가 아니며, 도구를 사용할 수 없으면 순차 모드로 사용한다.

대회에서 개인 스킬 반입·공개 저장소·설치·AI 도구가 허용되는지는 해당 본선 규칙을 적용해야 한다. 예선의 허용/금지 조건을 본선 규칙으로 가정하지 않았다. 공개 소스는 [arcturus0637-rgb/taskflow-kit](https://github.com/arcturus0637-rgb/taskflow-kit)에 제공한다. Git Clone 또는 저장소 ZIP 다운로드로 가져올 수 있다.

## 실제 과제 폴더에 등록

압축을 푼 팩의 `kit.py`를 기준으로 실행한다. PROJECT는 실제 과제 폴더로 바꾼다. 현재 소스 팩 폴더 자체를 대상으로 설치하지 않는다.

```text
python kit.py verify-bundle
python kit.py install --project PROJECT --dry-run
python kit.py install --project PROJECT
```

과제 폴더의 `.agents/skills/taskflow-*`에 다섯 스킬을, `.taskflow-kit`에 보조 도구와 수동 참고 원문을 배치한다. 기존 `AGENTS.md`와 과제 파일은 수정하지 않는다. 다른 내용의 기존 파일이 있으면 덮어쓰지 않고 중단한다. 같은 바이트의 재설치는 반복할 수 있다. 자동 업그레이드나 전역 설정 변경은 하지 않는다.

설치한 현재 세션이 새 스킬을 바로 발견하는지는 제공 환경에 따라 다르다. 발견하지 못하면 실제 과제 세션에서 `.agents/skills/taskflow-workflow/SKILL.md`를 직접 읽도록 요청하거나 환경의 공식 새 세션 안내를 따른다. Python이 없으면 `skills/taskflow-workflow/SKILL.md`부터 수동 참고할 수 있지만 SQLite 작업판·검사 증거 도구는 사용할 수 없다.

## 시작할 때 붙여 넣을 요청

```text
$taskflow-workflow을 사용해서 이 과제를 진행해줘.
원문을 읽고 목표·필수 요구사항·선택사항·제출물·제한·불확실한 점을 먼저 짧게 정리해.
기존 구조를 유지하고 실제 입력부터 결과까지 연결되는 최소 구현을 먼저 완성해.
실제 하위 에이전트 기능이 있으면 독립 작업을 병렬로 배정하고, 백엔드 안에서도 수정 범위와 공통 계약을 나눠줘.
내가 작업 중 개선 요청을 보내면 원문을 보존하고 담당자의 다음 작업으로 등록한 뒤 실제 전달 도구를 사용해줘.
등록·도구 전달 수락·착수·통합·검증을 구분하고, 새 요청 때문에 현재 작업 범위를 몰래 넓히지 마.
각 결과가 통합되는 대로 다음 가능한 작업을 진행해. 마지막에는 실제 요구사항과 검증 근거를 대조해줘.
```

## 확인 범위와 한계

작업 예약은 협력 규약으로, 에이전트의 임의 파일 수정을 OS 차원에서 차단하지 않는다. 같은 파일이 필요한 작업은 기다리거나 독립 사본에서 작업 후 통합해야 한다. 메시지 타임아웃 뒤 원격 전달의 정확히 한 번 처리는 보장할 수 없어 같은 요청 ID로 중복 방지를 한다.

스킬만으로 모든 과제의 정답·대회 점수·최적해·제출 성공을 보장하지 않는다. 원문 라이선스와 적용 범위는 각 upstream 폴더에 유지된다. 팩을 실제로 시험한 결과와 미확인 사항은 VALIDATION 문서에 분리해서 기록한다.
