# Understand Anything — final-result explanation

This is the TaskFlow adapter for the bundled Egonex-AI/Understand-Anything source. The original skill, nine original skill directories, agents, scripts and packages remain under `upstream/understand-anything/`; this adapter makes their paths and final-stage purpose explicit. Do not replace the upstream pipeline with a claim that merely reading this adapter generated a graph.

1. Apply **after implementation, integration and relevant checks**, before final handoff. Analyze the actual final task project and output, not the tool pack or an outdated checkout. If the user changes implementation during analysis, reconcile the change and refresh affected explanations/graph.
2. Run `python .taskflow-kit/kit.py understand-status --root PROJECT` (or the source kit's `kit.py`). This only inspects readiness. It never installs dependencies, dispatches agents or produces a graph. Use its resolved `plugin_root` and `original_skill`. Keep `PROJECT_ROOT` in the assigned workspace; use the returned scoped environment with `UNDERSTAND_NO_WORKTREE_REDIRECT=1`, never redirect to another worker's checkout.
3. For the graph, read `original_skill` and run the actual upstream pipeline with `--language ko --no-auto-update`. Substitute the **original skill directory** for `<SKILL_DIR>` and carry `CLAUDE_PLUGIN_ROOT=plugin_root` in the invocation environment. References to other understand-* skills mean the corresponding bundled original directory, not an assumed registered slash command. Exclude `.taskflow-kit`, `.agents`, `.taskflow`, dependencies and generated graph scratch from the subject; select the final implementation scope. Analysis workers read final sources and write only their assigned graph intermediates.
4. Upstream requires Node.js >=22, pnpm >=10 and a built core. Prepare the pinned workspace only when package installation/build is allowed: `pnpm install --frozen-lockfile`, then `pnpm --filter @understand-anything/core build`, with cwd=plugin_root. Never silently fall back to an unfrozen lockfile, enable Git hooks, alter global config, upload task data or run another model to bypass host limitations. If unavailable, report the concrete blocker, still provide a source-grounded explanation, and state that the graph/pipeline was not executed. Do not fabricate graph or fingerprint metadata. Start a dashboard only if requested and runnable.
5. Deliver a concise Korean `UNDERSTAND.ko.md` alongside the final result (outside a restricted submission set when necessary): purpose and actual behavior; how to run/use it; one input-to-output walkthrough; important files/components and their relationships; why the actual algorithm/design fits; checks performed; limitations and likely questions with honest answers. Cite actual paths and source locations, label assumptions, and separate observed results from inferred intent. For non-code outputs explain the actual deliverable structure and method; do not force a software graph onto an unsuitable artifact.
6. If the graph ran, validate it with upstream schema/review and link the actual `.ua/knowledge-graph.json` (or existing legacy directory), tour and optional dashboard. Preserve warnings and partial coverage. Recheck final source consistency before reporting completion. An unchanged Git commit does not prove freshness when there are uncommitted edits; force a full graph rebuild when needed. Evidence of installation, readiness, graph execution and full explanation are distinct states.
